# Masque

Local-first AI roleplay frontend. Wails v2 (Go backend) + React/TypeScript/Tailwind/shadcn-ui frontend, SQLite storage.

## Authoritative specs

The dev spec and vision doc live in `docs/`, which is **gitignored on purpose** — the specs must never enter git history. Read `docs/masque-dev-spec-m1.md` (authoritative) and `docs/roleplay-frontend-vision.md` (context) before making design decisions. Keep `docs/` in `.gitignore` (first entry) and never `git add -f` anything under it.

## Commands

- `make dev` — run with hot reload (`wails dev`; adds `-tags webkit2_41` automatically on distros that ship webkit2gtk-4.1 only)
- `make build` — production binary → `build/bin/masque`
- `make test` — `go test ./...`
- `make lint` — `golangci-lint run` (config in `.golangci.yml`)

`frontend/wailsjs/` and `frontend/dist/` are generated by Wails (gitignored). A bare `npm run build` in `frontend/` fails until `wails dev`/`wails build` has generated `frontend/wailsjs/`.

## Conventions

- Go 1.23+. No CGo introduced by our code: SQLite is `modernc.org/sqlite` (pure Go). Wails' Linux webview bindings are the one unavoidable cgo edge (needs `webkit2gtk` dev headers to build on Linux).
- All SQLite access goes through `internal/store`; services never touch `database/sql` directly.
- Migrations: embedded SQL files in `internal/store/migrations/`, named `NNNN_description.sql`, contiguous from 0001. Schema version tracked via `PRAGMA user_version`. **Never edit a shipped migration** — add a new numbered file.
- DB location: platform data dir via `internal/datadir` (Linux: `$XDG_DATA_HOME/masque` or `~/.local/share/masque`; macOS: `~/Library/Application Support/Masque`; Windows: `%APPDATA%/Masque`). One `masque.db` per install.
- Settings are key/value with JSON values; the frontend reads/writes them through the bound `settings.Service` (`Get`/`Set`/`DBPath`). `Set(key, null)` deletes.
- Wails-bound services live in `internal/<name>/service.go` as `Service` structs, constructed in `main.go` and passed to `Bind`. Frontend never talks to providers/network directly — everything goes through the Go core.
- Frontend: shadcn/ui components in `frontend/src/components/ui/` (new-york style, neutral base, CSS variables; Tailwind v4 via `@tailwindcss/vite` — theme tokens live in `src/index.css`, there is no tailwind.config). Import alias `@/` → `frontend/src/`.
- Tests: standard library `testing` only, `t.TempDir()` for scratch DBs. Provider integration tests (M1.2+) go behind a build tag.

## M1 build order (spec §12)

Each step ends in a runnable app; resist reordering.

1. **M1.1 — done**: Wails skeleton, SQLite + migrations, settings persist across restart
2. **M1.2 — done**: Provider abstraction + Ollama chat (hardcoded character, streaming end to end). Live-Ollama integration tests: `go test -tags ollama_integration ./internal/provider/ollama/`
3. **M1.3 — done**: OpenAI-compat + Anthropic providers, mid-chat provider switch. OpenAI-compat is live-testable keyless against Ollama's /v1 (`go test -tags openai_integration ./internal/provider/openai/`); Anthropic has an integration test behind `anthropic_integration` awaiting a real key
4. **M1.4 — done**: Card import (PNG/JSON, V2+V3) + characters screen. Committed fixtures in `internal/card/testdata/` are all original/synthetic (regenerate via `go generate ./internal/card`); real-world cards go in the **gitignored** `internal/card/testdata/smoke/` dir, which the smoke test picks up as independent data — never commit third-party cards
5. M1.5: Chat polish (swipes, edit, regenerate, persona, chat list/resume)
6. M1.6: Ollama manager + onboarding
7. M1.7: Dev mode (context inspector, sampler panel, endpoint config, log view)
8. M1.8: Packaging (AppImage/.deb, NSIS, dmg)

Out of scope for M1: voice, plugins, graph memory, lorebook injection, group chats, ST extensions, mobile, auto-update, telemetry, accounts.
