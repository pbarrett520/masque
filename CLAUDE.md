# Masque

Local-first AI roleplay frontend. Wails v2 (Go backend) + React/TypeScript/Tailwind/shadcn-ui frontend, SQLite storage.

## Authoritative specs

The dev spec and vision doc live in `docs/`, which is **gitignored on purpose** — the specs must never enter git history. Read `docs/masque-dev-spec-m1.md` (authoritative) and `docs/roleplay-frontend-vision.md` (context) before making design decisions. Keep `docs/` in `.gitignore` (first entry) and never `git add -f` anything under it.

## Commands

- `make dev` — run with hot reload (`wails dev`; adds `-tags webkit2_41` automatically on distros that ship webkit2gtk-4.1 only)
- `make build` — production binary → `build/bin/masque`
- `make test` — `go test ./...`
- `make lint` — `golangci-lint run` (config in `.golangci.yml`)

`frontend/wailsjs/` and `frontend/dist/` are generated by Wails (gitignored). A bare `npm run build` in `frontend/` fails until `wails dev`/`wails build` has generated `frontend/wailsjs/`.

## Conventions

- Go 1.23+. No CGo introduced by our code: SQLite is `modernc.org/sqlite` (pure Go). Wails' Linux webview bindings are the one unavoidable cgo edge (needs `webkit2gtk` dev headers to build on Linux).
- All SQLite access goes through `internal/store`; services never touch `database/sql` directly.
- Migrations: embedded SQL files in `internal/store/migrations/`, named `NNNN_description.sql`, contiguous from 0001. Schema version tracked via `PRAGMA user_version`. **Never edit a shipped migration** — add a new numbered file.
- DB location: platform data dir via `internal/datadir` (Linux: `$XDG_DATA_HOME/masque` or `~/.local/share/masque`; macOS: `~/Library/Application Support/Masque`; Windows: `%APPDATA%/Masque`). One `masque.db` per install.
- Settings are key/value with JSON values; the frontend reads/writes them through the bound `settings.Service` (`Get`/`Set`/`Delete`/`DBPath`). In Go, `Set(key, nil)` deletes; from the frontend always go through `setSetting()` in `frontend/src/lib/settings.ts`, which routes `null` to `Delete` — a JSON `null` argument never reaches a bound method (Wails v2 fails with "reflect: Call using zero Value argument" and the promise never settles).
- Cloud providers are **presets**: `internal/presets/presets.json` (embedded, data file — revise per release) lists each hosted API's format (`openai`/`anthropic`), base URL, key page, 2–4 pinned chat models, and `lastVerified`; plus `exclude_patterns` for filtering non-chat model ids. Provider ids in chats/settings are preset ids (`openrouter`, `groq`, `custom-openai`, …); keys live in `provider.<id>.api_key`, a `provider.<id>.base_url` setting overrides any preset's URL, and `provider.<id>.last_model` remembers the user's pick. `chat.Service.Catalog(id)` is what the model picker renders (Recommended = pinned ∩ listed, All = chat-filtered listing, Default never a non-chat model; a 401/403 sets `keyRejected`, a missing `/models` falls back to pinned). Ollama is not a preset. Verify every base URL and pinned id against official docs before bumping `lastVerified` — never from memory
- Wails-bound services live in `internal/<name>/service.go` as `Service` structs, constructed in `main.go` and passed to `Bind`. Frontend never talks to providers/network directly — everything goes through the Go core.
- Frontend: shadcn/ui components in `frontend/src/components/ui/` (new-york style, neutral base, CSS variables; Tailwind v4 via `@tailwindcss/vite` — theme tokens live in `src/index.css`, there is no tailwind.config). Import alias `@/` → `frontend/src/`.
- Tests: standard library `testing` only, `t.TempDir()` for scratch DBs. Provider integration tests (M1.2+) go behind a build tag.

## M1 build order (spec §12)

Each step ends in a runnable app; resist reordering.

1. **M1.1 — done**: Wails skeleton, SQLite + migrations, settings persist across restart
2. **M1.2 — done**: Provider abstraction + Ollama chat (hardcoded character, streaming end to end). Live-Ollama integration tests: `go test -tags ollama_integration ./internal/provider/ollama/`
3. **M1.3 — done**: OpenAI-compat + Anthropic providers, mid-chat provider switch. OpenAI-compat is live-testable keyless against Ollama's /v1 (`go test -tags openai_integration ./internal/provider/openai/`); Anthropic has an integration test behind `anthropic_integration` awaiting a real key
4. **M1.4 — done**: Card import (PNG/JSON, V2+V3) + characters screen. Committed fixtures in `internal/card/testdata/` are all original/synthetic (regenerate via `go generate ./internal/card`); real-world cards go in the **gitignored** `internal/card/testdata/smoke/` dir, which the smoke test picks up as independent data — never commit third-party cards
5. **M1.5 — done**: Chat polish (swipes, edit, regenerate, persona, chat list/resume). Swipe siblings share `messages.swipe_group` with exactly one active member; alternate greetings seed as a swipe group; default persona row falls back to the legacy `user.display_name` setting
6. **M1.6 — done**: Ollama manager + onboarding. Manager endpoints (pull/delete/ps/version) live on the ollama provider; `internal/ollamamgr` is the bound service (pull progress via the `ollama:pull` event, one pull at a time). Curated roster is embedded `internal/ollamamgr/starter_models.json` (data file — revise per release); the fit check tiers each model gpu/split/tight from need = `downloadBytes` × 1.2 + 1 GiB runtime against a usable GPU budget and RAM. `internal/sysinfo.DetectGPUs()` returns a per-device `Report` (never summed) and `Report.Best()` picks the single largest discrete GPU, ignoring integrated parts (Linux: nvidia-smi name/total/free + amdgpu sysfs total/used with `mem_info_vram_vendor` absence marking APUs, Intel by PCI bus; Windows: display-class registry `qwMemorySize` for all vendors + nvidia-smi free; macOS arm64: unified, budget = ⅔ of RAM ≤ 36 GB else ¾, the macOS default GPU wired limit). `ollamamgr.usableVRAM` = free (plus VRAM Ollama's own loaded models hold) − 512 MiB safety margin, or total − 1 GiB display reserve when free is unknown; integrated-only, no GPU, or failed detection → RAM-only budget, never a guess. The Recommended badge is computed (`chooseRecommended`: largest FitGPU model, else smallest, manifest flag only when nothing was measured). `Machine.Detail` carries exact MiB per device for logs/dev mode; the frontend rounds down. `minRamBytes` in the manifest is an optional floor only. First-run wizard shows only when both `onboarding.done` and `provider.default_model` are unset; test fresh-install flows by pointing `XDG_DATA_HOME` at a temp dir under `wails dev`
7. **M1.7 — done**: Dev mode. `dev.enabled` setting gates a Dev nav tab (full model manager via `ollamamgr.All`, endpoint config, request log) plus chat-screen sampler panel and per-reply context inspector. Inspector records persist in `messages.prompt_json` (migration 0003) — segment breakdown + exact wire request via each provider's `DescribeRequest` + ParamReport. Per-chat sampler overrides live in `chats.params_json` and now actually reach providers. `dev.streaming=false` sends stream:false (`ChatRequest.NoStream`); `dev.request_timeout_secs` bounds generations; `provider.{openai,anthropic}.context_window` override the static table. Request log is `internal/devlog` (in-memory ring of 200, keys never present)
8. **M1.8 — in progress**: Packaging. `make appimage` / `make deb` build Linux packages locally via `build/linux/*.sh` (AppImage bundles GTK + WebKitGTK through linuxdeploy + Tauri's gtk plugin; WebKit helper processes are copied in and an AppRun hook pins cwd to `usr/` because the plugin rewrites libwebkit's `/usr` paths to `././`). `build/darwin/dmg.sh` makes an ad-hoc-signed dmg; Windows uses `wails build -nsis` with `build/windows/installer/project.nsi`. `.github/workflows/release.yml` builds all three on a `v*` tag (or manually), smoke-launches each on a clean runner, and opens a draft release; `ci.yml` runs test/lint/build on pushes and PRs. Version comes from the tag and is stamped into `wails.json` `info.productVersion` (must be numeric x.y.z for NSIS/plist). Code signing is deferred until public release
9. **Cloud model picker (post-M1.8, 2026-10)**: fixed the first-tester bug where OpenAI's `/models` (embedding models first) became the default. Presets registry + `Catalog` + shared `ModelPicker`/`CloudProviderForm` components; migration 0004 moves a legacy `provider.openai.base_url` pointed away from OpenAI onto `custom-openai`
10. **Character view/edit (2026-10)**: tiles open a detail view (`CharacterDetail`), Chat on the tile is the fast path. One `CharacterForm` serves create and edit (core fields + collapsed Advanced, open in dev mode); `character.Service.Update` merges `CardForm` over the stored data object so unknown keys (lorebook, extensions) survive, `Duplicate` makes "Name (copy)", `ExportJSON`/`SaveExport` emit V3 that round-trips through Import. Delete is a **soft delete** (migration 0005 `characters.deleted_at`): chats stay, the list flags `characterDeleted`, `chat.State.CharacterDeleted` makes the chat read-only and Send/Regenerate/NewChat/OpenChat refuse with `errDeletedCharacter`. Future per-character fields (recommended model, lorebook links) go under the card's `extensions.masque`
11. **Starter characters (2026-10)**: Ember is gone. `internal/starters` embeds three original SFW cards (`cards/*.json`, V3 in the importer's format, marked `extensions.masque.starter`) plus avatars (`avatars/*.png`, generated by `avatars/gen.sh` with ImageMagick). `starters.Seed` runs from `chat.StartChat` once per install (`seed.starters` setting), inserting in reverse display order so the library shows WREN, The Narrator, Lǎo Zhāng; a fresh install lands on the Characters tab (no auto-opened chat). `starters.Restore` / `character.Service.RestoreStarters` (Settings button) re-add deleted starters and skip edited ones. Migration 0006 retires the old Ember row: untouched + no chats → removed, untouched + chats → soft-deleted, edited → kept. Cards' `mes_example` now goes into the system prompt and `post_history_instructions` is sent after the history (`ChatRequest.PostHistory`: trailing system message on Ollama/OpenAI, appended to the system block on Anthropic). Card prompts follow the research in the PR: positive rules only, under ~600 permanent tokens, voice carried by first message and examples

Out of scope for M1: voice, plugins, graph memory, lorebook injection, group chats, ST extensions, mobile, auto-update, telemetry, accounts.
